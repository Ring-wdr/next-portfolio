## 1. 절대 규칙

1. **사실을 지어내지 않는다.** 회사 경력, 기간, 팀 규모, 성과 수치, 사용자 수, 피드백 인용은 이 문서에 명시된 것 외에는 만들지 않는다. 모르는 값은 `TODO(user): ...` 플레이스홀더로 남기고, 작업 종료 시 TODO 목록을 보고한다.
2. **수치를 새로 만들거나 반올림/추정하지 않는다.** 기존 근거 없는 수치는 삭제하거나 TODO로 바꾼다.
3. **문체 규칙 (한국어 카피 전체에 적용):**
   - 실제로 한 일을 평이한 서술문으로 쓴다. ("~를 설계했습니다", "~를 옮겼습니다")
   - 금지: "A가 아니라 B" 대비 문장, 슬로건/격언형 문장, 수식어 과적, "X를 도입하지 않았다" 같은 부정형 성과, 묻지 않은 약점 스토리.
   - 금지 문자: em dash(—), 화살표(→, ⇒). 대신 쉼표나 "에서 ~로" 같은 말로 쓴다. 예: "jQuery에서 Next.js로".
   - 추상 카피 금지 예: "표면과 시스템을 함께 다루는", "노이즈 없는 전달", "에이전트 실행 표면", "움직임까지 설계된".
   - 기술 용어가 비개발자 대상 위치(카드 요약, 히어로)에 나오면 쉬운 말로 바꾸거나 괄호로 짧게 풀어준다.
4. **i18n:** 사이트는 다국어(hreflang)를 지원한다. 텍스트를 바꾸면 모든 로케일 파일을 같이 맞춘다. 번역이 애매하면 한국어를 우선하고 영어는 같은 의미로 간결하게.
5. **기존 테스트/CI를 깨지 않는다.** 콘텐츠 변경으로 스냅샷이나 테스트 기대값이 바뀌면 의도된 변경인지 확인 후 갱신한다.
6. 매 Phase 종료 시 검증 명령을 실행한다: `pnpm lint && pnpm test -- --run && pnpm build`
7. 수정 전 관련 파일 위치(프로젝트 데이터, about/timeline 데이터, 메타데이터, 컴포넌트)를 먼저 찾아 목록으로 보고하고 시작한다.

## Phase 1. 신뢰도 복구 (최우선, 콘텐츠만)

### 1-1. 근거 없는 수치와 피드백 제거
- 역대카(alltime-car): "렌트카 비교 시간 90% 단축", "평균 렌트 비용 15% 절감", "사용자 만족도 4.5/5.0 달성" 삭제.
- 법률사무소 대도(daedo-law): "콘텐츠 업데이트 시간 80% 단축", "고객 문의 처리 효율성 50% 향상" 삭제. (이 수치가 "배운 점 / 다음 단계" 칸에 잘못 들어가 있음)
- 모든 프로젝트의 출처 없는 "사용자 피드백" 인용 블록 삭제. 데이터 구조상 필드가 비면 해당 섹션 자체가 렌더링되지 않게 한다.
- 대체 문구는 확인 가능한 사실로만: 운영 도메인 여부, 공개 기간, 콘텐츠 양, 실제 기능.

### 1-2. 저장소/라이브 사이트와 어긋난 내용 수정
- POCAZ: "Socket.io를 활용한 실시간 통신"을 Supabase Realtime으로 수정 (저장소 package.json, README로 확인). "1인 프로젝트" 표기는 저장소 설명("과거 팀 프로젝트 마이그레이션")과 충돌하므로 `TODO(user): 원 프로젝트 팀 구성과 본인이 리메이크한 범위` 로 두고, 임시 문구는 "과거 팀 프로젝트를 혼자 다시 구현한 리메이크"로.
- 역대카: 실제 alltime-car.com은 "신차 장기렌트 가격 추적 플랫폼"이다. 프로젝트 설명을 실제 서비스 성격에 맞게 수정하고, 성격(개인/외주/참여), 본인 역할, 사이트에 보이는 견적/계약 건수에 대한 기여는 `TODO(user)`로 둔다. 숫자를 임의로 인용하지 않는다.
- 역대카 챌린지와 해결책 매칭이 한 칸씩 밀려 있음 (챌린지1 "실시간 가격 수집"의 해결책이 "가격 비교 알고리즘" 등). 챌린지3 "대량 데이터 처리 성능"은 해결책이 비어 있음. 올바르게 재매칭하고, 확인 불가한 항목은 챌린지째 삭제.
- 프론트엔드 주니어 스터디: 챌린지 "RSTest를 활용한 테스트 환경 구축"의 해결책이 "Biome 린팅 도입"으로 불일치. 재매칭.
- react-devtool-cli: "npm 버전 0.1.34"를 하드코딩하지 말고 현재 버전으로 갱신(가능하면 빌드 시 package 정보나 상수 한 곳에서 관리).
- 티키타카 TICKET: 비어 있는 "성과 / 주요 지표" 칸은 데이터가 없으면 섹션을 숨긴다.

### 1-3. 템플릿/플레이스홀더 문구 정리
- /project 상단 "각 프로젝트에는 간단한 설명, 스크린샷, 라이브 데모 또는 저장소 링크가 포함될 것입니다." 삭제 또는 완료형 한 줄로.
- /about 소개 본문의 일반론("HTML, CSS, JavaScript에 대한 깊은 이해…", "아름다운 제품을 만들기 위해 노력합니다") 삭제. 2절 사실 기반의 3~4문장으로 교체하되 미확정 부분은 TODO.
- 연차 표기 통일: "실무/학습 연차 3+", "3년 이상의 경험" 전부 "실무 4년"으로.
- 히어로 통계 "출시한 프로젝트 8+"에서 학습 레포(주니어 스터디)를 제외하거나 라벨을 "공개 프로젝트"로 변경.
- /project 기본 필터 "8 전체 프로젝트"인데 5개만 표시되는 불일치 수정 (기본 상태에서 전체가 보이게 하거나 카운트를 실제 표시 개수와 일치).
- /tech-stack의 "초보 코드에서 전문가 시스템으로" before/after 위젯(`const count = 0` vs `useState(0)` 수준)은 제거하거나 실제 프로젝트의 리팩터링 사례로 교체. 교체할 사례가 없으면 제거.

**Phase 1 완료 기준:** 사이트 전체에서 근거 없는 %, 만족도, 피드백 인용이 0건. 저장소와 충돌하는 기술 서술 0건. "포함될 것입니다", "3+", "학습 연차" 문자열 0건 (grep으로 확인해 결과 보고).

### 케이스 스터디: XMORSE 2.0 (프로젝트 목록 맨 앞)

- 제목: `XMORSE 2.0: jQuery 분석 플랫폼을 Next.js로`
- 메타: 스캐터엑스 · 2024.11 ~ 2026.03 · FE 2 / BE 4 / Infra 3 · 역할: 초기 세팅, UI 코어, 구조 설계
- 한 줄 요약:
  > 제조 데이터를 22종 차트로 탐색하고 수많은 차트를 한 화면에서 비교하는 분석 도구를, jQuery에서 Next.js로 다시 만들었습니다.
- 배경:
  > 기존 Scatter Analytics, Stick, Stonebreak를 묶은 XMORSE는 JSP 화면과 Spring 백엔드가 같은 포트에서 돌아서, 팀은 나뉘어 있어도 코드는 분리되지 않은 구조였습니다. 레거시는 클래스 이름으로 이벤트를 등록했고, select 하나를 바꾸면 data-type 값에 따라 서로 관련 없는 화면들로 분기가 갈렸습니다. 디버거로 콜스택을 따라가다 흐름이 끊기면 처음부터 다시 읽어야 하는 일이 잦았습니다.
- 프레임워크 결정:
  > 프로젝트 세팅 단계에서 Next.js를 제안했습니다. 회사는 널리 쓰이는 프레임워크를, 백엔드 팀은 서비스 분리를 원했습니다. 시각화 코어 하나를 서비스 화면, iframe 임베드 화면, 관리 화면이 같이 써서 서브 라우트를 관리하기 편한 구조도 필요했습니다.
- 구조 설계:
  > FSD를 참고해 계층을 나누고 화면 코드에서 API 호출을 떼어 냈습니다. openapi-typescript와 openapi-fetch로 백엔드 스펙에서 타입을 자동 생성했고, 서버 상태는 TanStack Query, 모달 상태는 overlay-kit으로 분리했습니다. 기존 Radix Dialog에 없던, 중첩 팝업을 위에서부터 순서대로 닫는 Dialog는 직접 구현했습니다.
- 임베드 화면:
  > 다른 서비스 위에 띄우는 차트 iframe은 SSR일 때 초기 렌더 시간이 일정하지 않아, 호스트가 3초 간격으로 메시지를 다시 보내도 받지 못하는 경우가 있었습니다. 이 화면을 SSG로 바꿔 첫 진입을 0.5초 이내로 줄였고, iframe이 수신 준비를 마치면 먼저 신호를 보내는 핸드셰이크 방식으로 바꿨습니다.
- 서버 렌더링 차트 그리드:
  > 서버에서 그린 차트 이미지를 띄우는 갤러리에서, 커서를 올리면 아이템 상세 데이터를 받아 커서 위치의 포인트에 툴팁을 표시했습니다. 옵션을 바꾸면 전체를 다시 부르지 않고 해당 아이템의 이미지와 옵션만 다시 조회했습니다.
- 검증:
  > 연산 로직은 유닛 테스트, UI 컴포넌트는 React Testing Library, 차트 코어와 iframe 화면은 Playwright E2E로 검증했습니다.
